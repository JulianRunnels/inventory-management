Factory Inventory Management System

A demo application made of two parts: a Vue 3 single-page app and a Python FastAPI service. It has no database. All data comes from JSON files that the API reads into memory when it starts, then filters on every request.

System overview

Three layers on one machine. The browser talks only to the API, and the API reads data only from files that are loaded once.

Tech stack

Intentionally small. There is no state library, UI kit, chart library, ORM or database.

Frontend

  • Vue 3 with the Composition API
  • Vue Router 4 using HTML5 history mode
  • Vite 8 dev server and bundler
  • axios as the HTTP client
  • Charts drawn by hand in SVG, layouts with CSS Grid
  • Requires Node ^20.19 or >=22.12

Backend

  • Python 3.11+
  • FastAPI for routing and OpenAPI docs at /docs
  • Pydantic v2 for response models
  • uvicorn as the ASGI server
  • uv for dependency management

Data & testing

  • 7 JSON fixture files in server/data/
  • Loaded once at import time, never written back
  • pytest + FastAPI TestClient in tests/backend
  • No frontend unit tests. Browser checks use Playwright MCP

Cross-cutting

  • i18n: English and Japanese (locales/en.js, ja.js)
  • The locale also picks the currency: USD, or JPY at a fixed rate of 150
  • A mock signed-in user lives in useAuth
  • scripts/start.sh / stop.sh run both servers

Data flow: a filter change

What happens when a user picks a warehouse in the filter bar on the Dashboard.

  1. FilterBar.vue writes to a shared ref in useFilters.js. The refs are declared at module scope, so every component that calls useFilters() shares the same state (a singleton).
  2. The view (for example Dashboard.vue) watches those refs and calls getCurrentFilters(), which maps the UI names to API names: selectedLocation becomes warehouse and selectedPeriod becomes month.
  3. api.js drops any value equal to 'all', builds a URLSearchParams query string, and sends a GET to http://localhost:8001/api/....
  4. FastAPI runs apply_filters() (exact match on warehouse; case-insensitive match on category and status) and then filter_by_month(). The month filter matches either a single YYYY-MM or a quarter such as Q3-2025, looked up in QUARTER_MAP.
  5. Pydantic validates the result against the response_model and serializes it. Summary endpoints calculate their totals on the fly from the filtered lists.
  6. Back in Vue, the raw response goes into refs such as allOrders and inventoryItems. Computed properties work out the KPIs, chart series and table rows, then the template re-renders.

Inventory has no time dimension, so /api/inventory ignores the period filter. Demand, backlog, spending and reports ignore all filters.

Observations

Things I found in the code that don't match the rest of the design. They're useful to know before you change anything.

The client calls endpoints the server doesn't have. api.js defines /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (GET, POST), but main.py implements neither. App.vue catches the task errors, so the failure goes unnoticed.
The Backlog view isn't routed. views/Backlog.vue exists and fetches data, but main.js registers no route for it.
Reports skips the API client. Reports.vue calls axios directly with a hardcoded localhost:8001 URL instead of going through api.js.
Quarter logic is duplicated. QUARTER_MAP and the if/elif chain in /api/reports/quarterly both encode the same 2025 quarters by hand.
Settings suited to a demo. CORS allows * together with credentials, the API base URL is hardcoded, and the data is read-only and resets on every restart.
